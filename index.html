01

Scaling an EV Platform to 500K+ Daily Transactions

Distributed Systems · EV Charging SaaS Platform · 99.9% Uptime
CONTEXT & CHALLENGE

Monolithic Bottlenecks Under Peak Load

As EV charger deployments expanded exponentially, peak driver charging periods caused severe synchronous request bottlenecks, degrading response times and causing database connection pool exhaustion.

OWNERSHIP & ROLE

Backend & Distributed Systems Lead

Owned distributed systems architecture, event-driven streaming design, low-latency caching patterns, and database query optimization from concept to production rollout.

TECHNICAL ARCHITECTURE DECISIONS
  • Apache Kafka Streaming: Decoupled high-frequency charging telemetry and payment validation from HTTP request-response chains, handling traffic bursts smoothly.
  • Redis Sentinel In-Memory Caching: Achieved sub-millisecond session lookup on high-traffic charger status endpoints, reducing database read load by over 70%.
  • PostgreSQL Query Optimization: Redesigned composite indexes and partitioned high-write transaction log tables to eliminate lock contention.
  • Kubernetes (EKS) Horizontal Pod Autoscaling: Configured proactive CPU/memory threshold scaling with zero dropped requests during sudden load spikes.
MEASURABLE OUTCOME
500K+ Daily transactions sustained
5× API latency acceleration
99.9% Production availability

03

EV Protocol Integration: OCPP 1.6/2.0 & OCPI Roaming

IoT & Protocols · EV Infrastructure · Hardware Interoperability
CONTEXT & CHALLENGE

Physical Hardware Quirks in a Digital Cloud

Connecting thousands of physical chargers from 10+ hardware manufacturers running different firmware versions revealed continuous non-compliant JSON payloads and dropped WebSocket connections.

OWNERSHIP & ROLE

Protocol Architect & Product Owner

Authored protocol adapter specifications, led integration testing in physical charger test benches, and engineered abstraction adapters isolating core charging logic from messy charger firmware.

ENGINEERING HIGHLIGHTS
  • State Machine Fault Tolerance: Created an asynchronous state machine with reconciliation timers that cleanly handle unexpected offline events mid-charge.
  • OCPP 1.6J to 2.0.1 Pathway: Designed a bidirectional message translator enabling forward-compatibility with advanced smart charging profiles.
  • OCPI 2.2 Roaming Integration: Connected external e-Mobility Service Providers (eMSPs) with token authentication, live session push, and CDR settlement.
MEASURABLE OUTCOME
−65% Hardware onboarding time
99.8% Session message delivery rate
